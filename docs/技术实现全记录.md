## 一、系统一句话 + 四大件分工

**手机上的「系统级定位守护 App」自动把 GPS 位置发到云端数据库，你在任何浏览器打开地图就能看轨迹、点按钮 8~25 秒叫出实时位置。**

| 角色 | 平台 | 大白话职责 |
|---|---|---|
| 📱 **手机端** | PhoneLocation（Kotlin 原生 App，v2.3.2） | 干活的：定时定位、上报、听命令、心跳 |
| 📦 **代码仓库** | GitHub `THATSCODEGUY/PHONE-LOCATION-SCRIPT`（公有） | 书架：存代码 + 免费云端编译 APK 工厂 |
| ⚙️ **服务端** | Vercel `phone-location-script.vercel.app` | 前台接待：收上报、排命令、托管地图页 |
| 🗄 **数据库** | Supabase（与他人共用一个项目） | 保险柜：存轨迹/命令/心跳，表名带 `phonelocation_` 前缀隔离 |

## 二、专业术语速查（懂这 18 个 = 看懂全系统）

| 术语 | 大白话 |
|---|---|
| **API / 端点** | 程序之间对话的窗口地址，如 `/api/report` 是"上报窗口" |
| **长轮询** | 手机挂在服务器的"窗口"上等 45 秒，服务器有事立刻答、没事到点放行——省电又实时 |
| **心跳** | 手机每分钟摸一下服务器证明"我在线"，地图靠它显示 在线/失联 |
| **被动模式** | 每 60 分钟自动报一次位置（画轨迹用，月流量 ~1MB） |
| **主动模式** | 你点[获取位置]→服务器排队命令→手机秒级领取→立即定位上报 |
| **DEVICE_KEY / ACCESS_TOKEN** | 两把钥匙：前者手机专用，后者看地图专用（`openssl rand -hex 32` 生成） |
| **service_role key** | Supabase 的"万能总钥匙"，只存在 Vercel 环境变量里，绝不出服务器 |
| **环境变量** | 填在 Vercel 后台的私密配置，代码用名字取值，仓库里看不到 |
| **前台服务（FGS）** | 带常驻通知的服务，安卓系统亲儿子，划不掉、被回收自动重拉 |
| **看门狗闹钟** | 每 15 分钟闹一次，发现服务停了就拉起 |
| **START_STICKY** | "被回收也要复活"的系统承诺 |
| **设备所有者（Device Owner）** | 把 App 登记为整台手机的"老板"：卸载/强停键变灰、开机必自启、系统清理不碰——**系统级保护** |
| **ADB** | 电脑通过 USB 线指挥手机的官方工具（platform-tools 里的 adb.exe） |
| **APK / 签名** | 安装包 / 它的"出厂印章"——印章不变，新版本才能覆盖安装不丢配置 |
| **CI/CD（GitHub Actions）** | 云端自动编译流水线：push 代码 → GitHub 免费机器编译出 APK |
| **GPS / 网络定位 / 精度** | 卫星定位（准、慢、免流量）→ 基站/WiFi 定位（快、糙）→ 精度=误差半径米数 |
| **outbox 补传** | 断网时上报先落盘手机，有网自动重发，数据不丢 |
| **电量守护上报** | 电量 ≤5% 时每 6 小时刷新最后位置 + 深度省电，把停报时间尽量推晚 |

## 三、定位与网络的边界（必懂常识）

| 环节 | 靠什么 | 要网络吗 |
|---|---|---|
| **定位（拿坐标）** | ① GPS 卫星 → ② 网络定位（基站/WiFi）→ ③ 最近已知位置兜底 | GPS **不需要**网络（卫星白送）；网络定位那一路需要 |
| **上报（发给地图）** | POST → Vercel → Supabase | **必须网络**（流量或 WiFi 任一） |

| 场景 | 结果 |
|---|---|
| 有 WiFi 没流量 | ✅ 一切正常 |
| 彻底没网 | ⚠ GPS 照常定位，坐标落盘手机等有网自动补传，一条不丢；地图显示"失联"只是暂时联系不上 |
| 室内 + 彻底没网 | ❌ 唯一死角 → v2.3.1 起兜底回传 24h 内最近已知位置 |

**借路人的蓝牙（离线查找网络）**：设备变低功耗蓝牙信标，路人手机匿名中继位置到云端。手机彻底关机后要有专用硬件芯片+预留电才能广播（App 层做不到）；国行无谷歌网络、小米网络不开放给第三方。可用替代：①小米「关机定位」开关（若机型支持，设置→安全→查找设备）②手机壳塞 BLE 防丢标签（¥50~200，没电后仍可寻回数月）。

## 四、整条龙实现过程（★ = 关键步骤）

### 阶段 ① 服务端三件套

```
Supabase 建库 → 跑 schema.sql → 拿两串凭证 → 生成两把密钥
```

1. Supabase 新建/复用项目（**共用库约定：所有表 `phonelocation_` 小写前缀**，防 Postgres 大小写折叠坑 ★）
2. SQL Editor 粘贴 `server/supabase/schema.sql` → Run → 3 张表 + 视图 + RPC（`FOR UPDATE SKIP LOCKED` 防命令被重复领取 ★）
3. Settings → API 抄 **Project URL**（⚠ 不带 `/rest/v1/` 尾巴）+ **service_role key**（⚠ 长的那个，不是 anon）
4. Git Bash 跑两遍 `openssl rand -hex 32` → 第 1 串 DEVICE_KEY、第 2 串 ACCESS_TOKEN
5. （收尾）pg_cron 挂每日清理（见运维手册）

### 阶段 ② GitHub 仓库

1. 网页建**空公有仓库**（⚠ 不勾 "Initialize with README" ★）
2. 命令三连（从此不需要 GitHub Desktop）：
   ```bash
   git remote add origin https://github.com/THATSCODEGUY/PHONE-LOCATION-SCRIPT.git
   git branch -M main      # master 改名 main，对齐脚本里的 /main/ 路径
   git push -u origin main # 以后每次只需 git push
   ```
3. 固定节奏：**改代码 → `git add . && git commit -m "版本: 干了啥"` → `git push`** → Vercel 自动重新部署、Actions 自动编译 APK

### 阶段 ③ Vercel 部署（5 分钟）

1. vercel.com 用 GitHub 登录 → Add New Project → Import 仓库
2. ★★★ **Root Directory 填 `server`**（漏了必失败，最关键一步）
3. Environment Variables 填 4 个：
   | 变量 | 值 |
   |---|---|
   | `SUPABASE_URL` | `https://<项目ref>.supabase.co`（无尾巴） |
   | `SUPABASE_SERVICE_KEY` | service_role 整串 |
   | `DEVICE_KEY` | 第 1 串 |
   | `ACCESS_TOKEN` | 第 2 串 |
4. Deploy → 用**生产域名**（`phone-location-script.vercel.app`），不是带随机码的部署快照（那个有登录墙 ★）
5. 验收 9 连测：正钥上报 ok / 错钥 401 / 轨迹读回含充电+SSID / 建命令 pending / 长轮询领取 / 二领 204 空……

### 阶段 ④ 手机端「系统级定位守护 App」

**演进教训**：Termux 是用户空间 App，HyperOS 定期后台清理必停 → 换**原生 App 四层保活**：前台服务 + 15 分钟看门狗闹钟 + 开机自启 + 设备所有者。

1. **代码 → APK**：Kotlin 源码 push → GitHub Actions 云端编译（不需要装 Android Studio）→ `git tag v2.3.x && git push --tags` → Release 自动挂 APK
2. **装配三件套放同一文件夹**：`PhoneLocation.apk` + platform-tools 解压的全部文件 + `setup-phone.bat`
3. **手机开门**（此生一次）：连点「OS 版本」7 次 → 开发者选项 → 开 **USB 调试**
4. **双击 bat 七步全自动**：装机 → 免弹窗授权 → 电池白名单 → 写配置启动 → 设备所有者
5. **设备所有者精确顺序 ★★★**（最刁钻的关卡）：
   ```
   登录小米账号 → 开「USB 调试(安全设置)」→ 退出所有账号
   → 立刻 adb shell dpm set-device-owner ... → Success → 重新登录账号
   ```

### 阶段 ⑤ 验收三板斧

| 测试 | 通过标准 |
|---|---|
| 挂机 1~2 小时 | 跨过后台清理时间点心跳持续在线 |
| 重启手机 | 2~5 分钟内心跳自动变绿 |
| 点[获取位置] | 8~25 秒出位（定位失败也有 24h 内旧位兜底） |

## 五、日常运维手册（以后只看这节）

### 想调什么 → 跑什么

| 目的 | 操作 |
|---|---|
| **改上报间隔**（如 60→10 分钟） | 电脑：`.\adb shell am start -n com.thatscodeguy.phonelocation/.MainActivity --es device_key <DEVICE_KEY> --es device_name primary --ei passive_min 10` |
| **看手机状态** | 打开 App：服务状态 / 最后上报 / 最近结果 / 轮询次数 / 待补传 / 设备所有者 |
| **立即测一次上报** | App 点「测试上报」 |
| **升级 App** | GitHub → Releases → 下载新 APK → 手机覆盖安装（配置全保留） |
| **改轨迹保留期** | Supabase SQL Editor 重跑 `cron.schedule`（同名覆盖，改 `'3 days'` 数字即可） |
| **地图地址** | `https://phone-location-script.vercel.app/map?token=<ACCESS_TOKEN>` |
| **彻底删除清理任务** | `select cron.unschedule('phonelocation-cleanup');` |
| **解除设备所有者** | App 状态页一键「解除设备所有者」，或电脑 `.\adb shell dpm remove-active-admin com.thatscodeguy.phonelocation/.DeviceAdmin` |

### 当前清理任务（已上岗）

```
jobid=1 · phonelocation-cleanup · 每天 04:00 UTC
轨迹留 3 天 · 命令日志留 30 天
```

### 地图按钮

| 按钮 | 作用 |
|---|---|
| 跟随 | 开=自动居中最新位置；关=自由拖动 |
| 刷新全量 | 重拉全部历史轨迹（最多 500 点） |
| 隐藏低精度 | 精度>150m 的毛刺段弱化成灰虚线 |
| 刷新间隔 | 地图拉新数据的频率；点[获取位置]后调快看得爽 |
| 获取位置 | 按需实时定位（被动轨迹每小时自动来，不用手点） |

## 六、关键卡点全记录（17 个真实关卡 + 解法）

| # | 现象 | 病因 | 解法 |
|---|---|---|---|
| 1 | Termux 装完老停报 | 用户空间 App 挨不过 HyperOS 定期清理 | 换原生 App + 设备所有者 |
| 2 | 首次 push 冲突风险 | 建仓库时勾了 README 初始化 | 建空仓库 + `git branch -M main` |
| 3 | 手机一键命令失效 | install.sh 里 REPO_BASE 是占位符 | v2.2.1 写死真实仓库地址再 push |
| 4 | 中文文件下载失败 | raw 直链中文要 URL 编码 | `HYPEROS-%E4%BF%9D...md` 编码写法 |
| 5 | Supabase 表可能跟人撞名 | 共用项目 | 全表 `phonelocation_` 小写前缀（v2.2.2） |
| 6 | 地图显示不出充电/WiFi | locations 接口 select 漏字段 | v2.2.2 修复，线上验收通过 |
| 7 | CI 编译失败 ×3 行 | `setLineSpacing` 参数要 float、`fillViewport` 无属性语法 | `.toFloat()` / 改 `setFillViewport(true)` |
| 8 | bat 一运行满屏乱码 | UTF-8 中文 vs cmd 的 GBK 解析 | 重写为纯 ASCII 英文版 |
| 9 | `INSTALL_FAILED_USER_RESTRICTED` | HyperOS「USB 安装」开关没开 | 开发者选项打开 + 装时盯手机点允许 |
| 10 | `unauthorized` | 手机授权弹窗没点 | 勾「始终允许」→ 确定 |
| 11 | App 一小时后停报、状态页归零 | ①权限被系统回收 ②后台清理强停 | ①手机手动「位置→始终允许」②设备所有者 |
| 12 | 点重启服务就异常退出 | startForeground 遇缺权限直接停进程 | v2.3.1 权限预检 + try/catch 兜底 |
| 13 | 点[获取位置]心跳变红 | 定位尝试期心跳空窗 > 3 分钟阈值 | 阈值 3→5 分钟 + 定位失败旧位兜底 |
| 14 | `dpm: Calling identity is not authorized` | 「USB 调试(安全设置)」重启后自动关闭 | 登账号→开开关→退账号→立刻设 |
| 15 | `dpm: already some accounts` | 设备上还有账号残留 | 设置→账号与同步 全部删光再设 |
| 16 | 设备名错位叫不醒 | App 报 `redmi-note15pro`、地图认 `primary` | am start 改名；v2.3.1 起默认 primary |
| 17 | SQL 批量跑失败全滚回 | unschedule 首次跑必错 + SQL Editor 整批一个事务 | 去掉 unschedule，schedule 同名自动覆盖 |

**两条规律**（记住受用）：
- **PowerShell 不认当前目录的命令** → 前面加 `.\`
- **adb 授予的权限重启可能被收回** → 涉及权限的尽量手机手动设（正规授予永不回收）

## 七、出问题排查决策树

```
地图失联？
├─ App 状态页「服务: 未运行」→ 点「重启服务」
│   ├─ 提示缺权限 → 设置→应用管理→权限→位置→始终允许 → 再重启
│   └─ 起来了 → 观察（设备所有者已装，应极少发生）
├─ 服务在跑但没网 → 查手机流量/WiFi；有网自动补传（待补传>0 会显示）
└─ 手机关机/没电 → 等；彻底找不到走 i.mi.com 兜底

[获取位置] 空转？
├─ 到窗边/室外再点（室内 GPS+网络都可能拿不到）
└─ 还不行 → App 看「最近结果」；v2.3.1 起 24h 内旧位置也会兜底回传
```
